1. Executive Summary

Thredo is currently a user-facing B2B thread marketplace where traders browse products, match threads by image, discover companies, and manage wishlists. The app has a single navigation shell and all APIs use the user/ namespace. The login response already includes a role field, but it is not used for routing or UI branching.

This document defines requirements to introduce a Company role so registered companies can:

  • View and manage only their own products on a familiar Home-like experience
  • Use Product Reel and Product Detail with appropriate restrictions
  • Keep Category browsing unchanged
  • Exclude the Thread Match (image scan) feature
  • Access a new Company List with an approval workflow for cross-company product visibility
  • Use a dedicated Profile layout showing full company details

5. Company List & Approval Workflow

5.1 Access States

StatusCan view peer products?UI action
NoneNo"Request Access" button
PendingNo"Request Pending" badge
ApprovedYesNavigate to peer products (read-only)
RejectedNo"Request Rejected" + re-request policy TBD

5.2 Request Flow

Company A → Company List → Select Company B
    → POST company/access-requests { target_company_id }
    → Status: Pending

Company B → Incoming Requests
    → Accept → Company A can view B's products
    → Reject → Access denied

9. Security Rules

  • Server enforces company_id from token — client cannot override
  • Peer products require approved access request
  • Company role blocked from wishlist and match-thread APIs
  • Peer product detail is read-only

11. Acceptance Criteria

  1. User role experience unchanged
  2. Company lands on 4-tab shell (no Match)
  3. Company Home shows only own products
  4. Category UI unchanged; products scoped to own company
  5. Product detail hides wishlist & embroidery match for company
  6. Company list shows access status per peer
  7. Request / accept / reject workflow functional
  8. Approved peers' products viewable read-only
  9. Separate company profile layout with full details
